HD2 弹药叠加层（Helldivers 2 Ammo Overlay）
====================================================================

给《绝地潜兵 2》用的屏幕覆盖层：实时读取左下角弹药计量的剩余量，
在屏幕上画一条对应长度的横条——满弹白条、低弹整条红、打空只留灰轨。

全程只做屏幕像素分析：不读游戏内存、不注入进程、不修改游戏文件。


目录结构
--------------------------------------------------------------------
hd2-ammo/       第一代（已冻结，不再改动）
hd2-ammo-v01/   第二代：新增红色弹药通道、空壳通道
hd2-ammo-v02/   第三代（当前活动版）：HUD 布局自适应 + 单文件 exe

所有后续改动都落在 hd2-ammo-v02/，前两代只作历史对照。
文件名以 _ 开头的 .py 是开发当时的验证 / 测量脚本，不是主程序。


v02 主程序
--------------------------------------------------------------------
main.py         打包入口。同一个 exe 按参数分派身份：
                    不给参数     = 启动器（拉起 Steam 里的游戏 + 挂叠加层）
                    --overlay   = 纯叠加层本身（启动器派生自己时用）
                    --daemon    = 守护模式，谁把游戏拉起来就跟谁走
                    --no-launch = 不主动拉游戏，只等它自己出现
launch.py       启动器 / 守护逻辑，负责派生叠加层、盯进程生死
live_ammo.py    主循环：截图 → 识别 → 刷新覆盖层 → 热键
ammo_detect.py  识别核心：白色 / 红色 / 空壳三条通道 + HUD 布局判据
overlay.py      分层点击穿透窗口（Win32 UpdateLayeredWindow）
capture.py      截图（mss）与配置读写
hotkeys.py      全局热键注册
crosshair.py    独立小工具：识别准星圆环，在环上盖一个绿色十字（F2 开关）
tune_arc.py     弧线外观调参器
build_exe.py    打包成单个 exe


用法
--------------------------------------------------------------------
源码运行（Python 3.11+，依赖 numpy / mss / pillow）：

    python live_ammo.py            直接跑叠加层
    python launch.py               拉起游戏 + 挂叠加层，游戏退出自动收摊
    python launch.py --daemon      常驻守护，谁起游戏就跟谁走

打包：

    python build_exe.py
    产物：dist/HD2弹药叠加.exe（单文件，双击即启动器）
    exe 首次运行会把内置 config.json 释放到 exe 旁边，之后改旁边那份才生效。


热键
--------------------------------------------------------------------
F1    叠加层 开 / 关
F2    准星十字 开 / 关（crosshair.py）


让 Steam 启动游戏时自动挂上叠加层
--------------------------------------------------------------------
Steam → 库 → 右键 Helldivers 2 → 属性 → 启动选项，填入：

    cmd /c start "" "<仓库路径>\hd2-ammo-v02\dist\HD2弹药叠加.exe" --no-launch && %command%

要点：
  - 必须用 start，直接写 exe 路径的话 cmd 会同步等待，而叠加层要等游戏，
    游戏就永远起不来。
  - 必须带 --no-launch，否则 exe 会按启动器身份再用
    steam://rungameid/553850 拉一次游戏。


识别口径（v02）
--------------------------------------------------------------------
余量 = 弹匣体内的白像素数 ÷ 弹匣体面积
弹匣体 = 白像素最大连通域的凸包，向内缩进一个外框线宽（2px）

三条通道：
  白    正常弹药，参与百分比计算
  红    低弹时游戏会把整个弹药计量器转红，白色像素整条消失。
        红色单独走一条通道，只回答「是不是低弹红」，绝不进百分比分子。
  空壳  打空后只剩一圈轮廓线，白像素面积会低于门槛。
        此时改看形状（连通域形状与模板的 IoU），判为 0%。

显示：
  满弹 → 白条     低弹 → 整条红     打空 → 0% 灰轨


HUD 布局自适应（背包 / 无背包）
--------------------------------------------------------------------
背着补给背包与不背时，左下角的弹药图标会整体左移 106px。

判据：矩形 (330,1250)-(337,1295)（以 2560x1440 为基准）内有没有一条
白色竖线——那是背包图标与弹药区之间的分隔线。
最长竖直连续亮段 ≥ 24px 判为「有背包」，否则按无背包处理。

每秒判断一次，自动切换检测框位置，不需要手动设置。


分辨率
--------------------------------------------------------------------
所有坐标与尺寸参数按 2560x1440 标定，运行时按屏幕高度等比缩放。


注意
--------------------------------------------------------------------
- 三个版本注册的是同一个 F1 全局热键，同一时间只能跑一个。
- 纯屏幕像素分析，不读写游戏内存、不注入、不改游戏文件；
  使用方式与风险请自行评估。
- 仓库不含 _out/（开发过程对照图）、_ch/、_exe/、dist/、logs/ 等
