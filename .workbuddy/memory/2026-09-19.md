## 01:16 布局判据节流改为「每秒一次」（用户要求）

- 需求原话：「改成每秒判断一次有没有背包」。原实现按帧数节流（`layout.check_every=5`），
  在 50Hz 下等于 0.1 秒判一次 —— 既没必要，而且采样率一变节流频率就跟着变。
- 改法：`LayoutProbe.check_every`（帧）→ `interval`（秒，默认 1.0）；
  `MultiRegionDetector._layout_countdown` → `_layout_next_t`（`time.monotonic()` 时刻）；
  `probe_layout()` 里 `if now < self._layout_next_t: return`。
  首帧 `_layout_next_t=0.0` 所以开机第一帧立刻判一次；
  `force_layout()` 解除强制时重置为 0.0，下一帧立刻重判。
- 顺手修掉一处白干：`probe_layout` 原来先算 `longest_run()` 存 `last_run`，
  又调 `has_backpack()` 把同一张图**再扫一遍**；现在只扫一次，
  `apply_layout(self.last_run >= self.layout.min_run)`。
- config：`layout.check_every: 5` → `layout.interval: 1.0`，注释同步；
  live_ammo 启动横幅加一行「每 1 秒重判一次」。
- 验证（新脚本 `_layout_rate.py`，给 `longest_run` 套计数器）：
  50Hz / 20Hz / 5Hz 三种采样率各跑 2.5 秒 → 判据实跑都是 **3 次 = 1.00 次/秒**，
  与采样率无关；布局结论仍正确（自动有背包）。
  `_layout_test.py` 4/4 正确、`_red_test.py` 误报 0 + 合成红帧 4/4、
  `_final.py` 剪影 8/8 拒绝。50Hz 满速 **9.34ms/帧**（改前 9.70ms，省的正是那次重复扫描）。
- 只动 hd2-ammo-v02；`hd2-ammo/`（09-18 23:52）与 `hd2-ammo-v01/`（09-19 00:31）时间戳未变。
