# 本项目长期约定

## 目录与版本（强制）

- `hd2-ammo/` = 第一代冻结版，**不要再改**。
- `hd2-ammo-v01/` = 第二代（红色通道 + 空壳通道），已冻结。
- `hd2-ammo-v02/` = **活动版**，所有改动落这里。
- 新建下一版沿用同一命名：`hd2-ammo-v03`……（整目录复制，去掉 `__pycache__`，改完在该目录冒烟）。
- 三个版本都会注册 `F1` 全局热键 → **同一时间只能跑一个版本**，否则后启动的报「注册失败」。

## HUD 布局自适应：背包 / 无背包（v02）

- **需求**：用户两张截图指出——背着补给背包与不背时，左下角弹药 HUD 整体平移，弹匣图标换位置。
  判据由用户指定：矩形 **(330,1250)-(337,1295)** 里有没有一条白色竖线（背包图标与弹药区之间的分隔线）。
- **实测**（2560x1440，把用户 1920x1079 截图放大到 2560 后量）：
  - 有背包：竖线在判据矩形内，最长竖直连续 **26px**；弹匣在 x361~383（= config 现坐标 330~390 覆盖）
  - 无背包：同位置只剩弹药数字笔画，**8px**；弹匣左移到 x255~275
  - 纯背景 0px；另一张实机满弹帧 38px。12 帧连跑读数零抖动。
  - **位移 = −106px（x），y 不变**：质心法对齐（弹匣在区域内的相对位置），偏离 0.31px。
- **实现**（`ammo_detect.py`）：`LayoutProbe`（`longest_run()` 逐行扫描最长竖直连续亮段，
  `has_backpack()` = `run >= min_run`）+ `MultiRegionDetector`：
  - **一次抓 canvas**（= 判据矩形 ∪ 区域原位置 ∪ 区域平移位置 = (224,1250)-(390,1300) 166x50），
    判据与区域都从这张图切；mss 抓取成本与尺寸几乎无关（60x50=8.61ms vs 166x50=8.77ms），所以不拆。
  - 布局切换时 `_reset_temporal()` 清 EMA/去抖，避免把上一种布局的读数带过来。
  - **节流按秒不按帧**：`layout.interval`（默认 1.0 秒）用 `time.monotonic()` 卡点，
    判一次 ~0.7ms；非检查帧沿用上次结论。改成按秒是因为采样率可变（50/25Hz、卡顿掉帧），
    帧数节流会让判据频率跟着变。实测 50/20/5Hz 三种采样率下都是**恰好 1 次/秒**。
  - `probe_layout` 只扫一遍 `longest_run`，直接喂给 `apply_layout`（原先是 `has_backpack()`
    又扫一遍，白花一次）。
- **config**：`layout` 段 = `probe_rect / shift / min_run(24) / lum(130) / interval(1.0) / enabled`。
  **B 区域已删除**（被「单区域 + 平移」取代）；`interior_mask.npy` 不再使用。
- **热键只剩 F1**（开启/关闭）——布局全自动，手动切换已无意义；标定用 `--layout bag|nobag`。
- **性能**：50Hz 满速 `9.34 ms/帧`（v01 对照 `10.08 ms`）。

## 弹药余量口径（v01 起，用户拍板）

- 一句话：**余量 = 弹匣体内的白像素数 ÷ 弹匣体面积**。
  弹匣体 = 白像素最大连通域的凸包内缩 `detect.fill_inset`（= 外框线粗细 2px）。
- 不做开运算；**百分比分子里永远只有白像素**。
- 实测标定（2560x1440 区域 A）：满弹 93% → `snap_full` 冻成 100%；用户参考帧 22% → 阈值 0.22。

## 红色通道（v01，2026-09-19 补）

- **存在的理由**：HD2 在余量低于阈值时把整个弹药计量器转红（官方行为 "flashing red ammo gauge"），
  白色像素整条消失 → 纯白口径判 `invalid` → 覆盖层**整窗隐藏**，低弹这一档完全缺失。
  用户原话：「之前只算了白色像素，现在对于红色弹药的显示是没有检测规则的。」
- **规则**：红色单独一条通道，**只回答「是不是低弹红」，绝不进百分比分子**。两条路径：
  1. 白通道成功定位（外框仍白）+ 弹匣体内红像素 ≥ `red_min_px` 且占比 ≥ `red_body_frac`
     → `state="low"`，`hint` 带 `+red`；
  2. 白通道失败 → `_fail()` 里先过 `_red_reading()`（红像素自成弹匣形状，过同样的
     形状 IoU + 窗口邻域校验）→ `state="low"`，`hint="red"`。
- `state` 取值：`white | low | empty | none`。`fraction` 在 low 档 = 红像素占弹匣体比例。
- 显示端：`overlay.decide_show(fraction, fill, low, o)` 是**唯一的判定函数**，
  `show_value` 与出图脚本共用，避免两处口径漂移。`low=True` 优先级最高。
- 参数（`config.json` → `detect`）：`red_chroma`=55、`red_min`=120、`red_min_px`=25、
  `red_body_frac`=0.2、`red_shape_min_iou`=0.4。
- 验证：8 张真实素材 × 2 区域**误报 0**；合成红帧 4/4 命中。注意「红框」若在弹匣体**外面**
  （如画面里套住图标的红框）不会触发 —— 只有体内变红才算，这正是防误报的设计。

## 空壳通道（打空态，v01，2026-09-19 补）

- **用户报的 bug**：「没子弹的时候不是空条而是啥都没有」。
- **根因（实测数字）**：打空时游戏把填充清空、只留一圈轮廓线 → 白掩膜从满弹 544px 掉到
  **142px**（用户样本 122px），低于 `mask_floor = 30% × 窗口面积 = 145`（区域 A）。
  → 判「无弹匣」→ 红色通道也无红 → `valid=False` → `hide_on_invalid` 把**整窗隐藏**。
  但形状是完好的：凸包 IoU **0.877**（构造空壳）/ **0.59**（用户样本），门槛只要 0.46。
- **修法**：`RegionDetector._shell_reading()`，接在 `_fail()` 里、红色通道之后。
  白掩膜**面积不足**时改看形状：`n < mask_floor` 且 `n >= shell_min_px(40)`、
  形状 IoU ≥ `shell_min_iou(0.52)`、落在窗口邻域、体内既无白填充（≤ `empty_frac`）也无红填充
  → `valid=True, fraction=0, state="empty", hint="shell"`。
  门槛 0.52 比白通道的 0.46 严，因为这一档没有面积背书。仅在有 `window` 时启用。
- **显示结果**：`state="empty"` → `decide_show` 返回 `(0.0, False)` → 画 0% 空轨（只剩灰轨），
  窗口不再隐藏。这正是用户要的「空条」。
- **验证**：构造空壳与用户样本均判 `empty`；真实素材 16 例误报 0；A 区剪影 8/8 拒绝；合成红帧 4/4 命中。
- 对照图：`hd2-ammo-v01/_out/空弹显示.png`（打空=灰轨 / 低弹=整条红 / 满弹=白条）。

## 打包 exe（v02，2026-09-19 补）

- `python build_exe.py`（或双击 `打包exe.bat`）→ 产物 **`dist/HD2弹药叠加.exe`**，
  单文件 onefile + `--windowed`（无黑框），26.3 MB。改了代码要重新打一次包。
- **一个 exe 两种身份**，由 `main.py` 分派：
  - 默认（不给 `--overlay`）= **启动器**：拉 Steam 里的 HD2 → 挂叠加层 → 游戏退出自动收摊；
  - 带 `--overlay` = **叠加层本身**。启动器派生自己就靠这个参数，
    因为打包后 `sys.executable` 就是 exe，没法再拼「解释器 + live_ammo.py」。
  - 两个都注册 F1 → 只有 `--overlay` 那一份注册热键，启动器那份不注册，不冲突。
- **frozen 路径规则**（`capture.py`）：`app_dir()` = exe 旁边（可写：config.json / logs/），
  `res_dir()` = `_MEIPASS` 解包目录（只读：assets/*.npy）。
  首次运行把内置 config.json **释放到 exe 旁边**，之后改旁边那份才生效。
  `launch.py` 的 `HERE` 与 `live_ammo` 的日志目录都改走 `app_dir()`。
- **坑**：PyInstaller 的 `--add-data` 用相对路径时按 `--specpath` 解析 → 必须给绝对路径，
  否则报 `Unable to find ..._exe\config.json`。
- **坑**：`--windowed` 的 exe 被控制台父进程启动时 stdout 仍然可用；被本 exe 派生
  （CREATE_NO_WINDOW + 重定向到文件）时 `sys.stdout is None` → live_ammo 自己落盘到 logs/。
  所以排查只能看 `logs/live_*.log` 与 `logs/ammo_*.log`。`launch.py` 里 `sys.stdout.flush()`
  必须判 None。
- 实测（冻结版）：50Hz 单帧 9.4~10.0 ms；`[覆盖层] 已上屏 矩形=(1405,540)-(1508,900)`；
  启动器派生 → 子进程退出 → 收摊，两端日志都正常。

## 准星圆环 → 绿色十字（crosshair.py，v02，2026-09-19 起）

- **独立脚本** `hd2-ammo-v02/crosshair.py`（不依赖 capture.py/overlay.py，也不改 config.json）：
  屏幕正中 mss 截 300x300，识别准星**那个空心圆环**（着弹点指示），在环上盖绿色大十字，50 Hz，F2 开关。
  配套 `启动_准星十字.bat`。`--replay 帧目录` 可离线跑并出对照图。
- **横线不参与定位**（用户明确纠正：「横线可不是弹着点」）。横线、中心小方块只当背景。
- **环几何**（2560x1440 尺度）：外径 22~23px、线宽 2~3px、中径 ≈ 9.5~10.5。
  环绕中心块上下都跑（上 16px / 下 21px 都见过），**整组准星在屏幕上也会移动**，别假设横线固定在中心。
- **判据**：提亮图（亮度 − 大核均值）命中率的「环带 − 内盘(16px) − 远场(62px)」，取峰值为圆心。
  远场窗口必须 ≳ 环外径的 2.5 倍，压到环带上会自相抵消、把真环峰挪到背景上。
- **阈值** 0.45 显示 / 0.38 隐藏。实测 ≥0.49 的人工资核对 6/6 全对，0.26~0.44 段 9/10 是误检
  （爆炸、岩石纹理、红色 UI 字）；用户不要求 100% 正确，爆炸模糊场景误检可接受。
- 尺寸参数按 `ref_h=1440` 标定，运行时按屏幕高度等比缩放。
- **易错点**：子图若为给邻域滤波加了 padding，坐标映射必须用子图原点而不是搜索区原点，
  否则整体偏 +pad（本项目踩过，偏 34px）。
- 性能：mss 抓 300x300 ≈ 6.9ms + 检测 ≈ 7ms + 分层窗口 blit ≈ 1.6ms ≈ 15.4ms/帧（65 fps）。
